# Live read-only receipts: 2026-10-24

Four built-in connectors were run against maintainer-owned test accounts and
one public repository. Each receipt below is one bounded run: one account,
subscription, project or repository, on one day, at one source commit. It shows
what this adapter collected from that scope. It does not qualify a published
release artifact, other tenants, larger estates or provider-wide coverage.

Every run used the same sequence: `connectors probe`, `connectors configure
--state enabled` with the same credential and option JSON, `connectors sync`,
`assessment status`, `assessment violations` and `assessment stale-evidence`, then a
second `connectors sync` to check recollection. All access was read-only. No
provider resource, role, policy or repository setting was created or changed.

### Redaction method

Account IDs, subscription and tenant IDs, project IDs and numbers, ARNs,
principal names, emails, External IDs, tokens and raw evidence are omitted
rather than hashed. These identifiers have low entropy, so an unsalted hash
could be reversed by enumeration. Event types, statuses, counts, durations,
coverage-gap reasons and control IDs are published. The raw ledgers and command
output were kept locally only for the run and then deleted. Before publication,
this file was checked for 12-digit numbers, ARNs, GUIDs, emails, project paths
and token prefixes. The [qualification tests](../../../tests/test_connector_qualification_doc.py)
repeat that check.

### Independent count check

Each count was reconciled with the provider's own CLI, using the same read-only
identity: `aws`, `az`, `gcloud` and `gh api`. A "match" below means the
connector's row count equals the provider's listed count for that resource type
in that scope. It does not show that the provider listing is complete.

### What every run established

- Probe, configure and sync succeeded. `evidence_count` equalled the raw row
  count and the evidence-freshness count. All rows were fresh, with no stale or
  expired evidence.
- Raw, bronze and silver row counts were equal and every event ID was unique.
  Raw hashes matched bronze and no silver hash was missing.
- A second sync returned the same count and kept the raw ledger at that size.
  Stable event IDs were upserted rather than duplicated.
- `stale_controls` lists `SOC2-CC6.1` in every run. Its control test also
  requires `identity.access_review`, `compliance.evidence_bundle` and
  `secret.finding`, which none of these connectors supplies alone. That is
  missing evidence, reported as such, not stale data.

## github-security

| Scope                                             | Probe                     | Sync      | Recollect | Rows |
| ------------------------------------------------- | ------------------------- | --------- | --------- | ---- |
| One public repository (`koda-ai-studio/grc-lake`) | ok (`config_only`), 0.3 s | ok, 4.2 s | 6, 4.4 s  | 6    |

- **Principal:** the maintainer's GitHub CLI OAuth token, passed only through
  the `GITHUB_TOKEN` environment variable. Its scopes (`repo`, `read:org`,
  `workflow`, `gist`, `write:packages`) are broader than the catalog's GitHub App read
  permissions. This is not a GitHub App installation test. Every request was
  a GET.
- **Rows (6):** one each for branch protection, collaborators, teams, workflow
  permissions, security settings and security findings. The security-findings
  row is open.
- **Count check:** 2 collaborators, 0 teams, 32 code-scanning alerts (0 open),
  0 secret-scanning alerts and 3 Dependabot alerts (1 open, 2 fixed). All
  matched `gh api`.
- **Bug found and fixed:** the first sync on `a523b116` failed with
  `HTTP Error 400: Bad Request`. GitHub rejects the `page` parameter on the
  Dependabot alerts endpoint and pages only by `Link` cursors. The adapter now
  follows those cursors, accepting continuation only on the same host and
  endpoint. The fix has regression tests in
  [`test_github_collection_contract.py`](../../../tests/test_github_collection_contract.py).
  All final runs, including the cloud runs, used the fixed commit.
- **Probe limitation:** the probe validates configuration only and does not
  contact GitHub. A green probe preceded the failing sync. The probe result is
  labeled `config_only`, and the [GitHub contract](../../GITHUB_QUALIFICATION.md)
  documents this.
- **Assessment:** 7 controls: 3 failing, 4 not evaluated. 3 high open
  violations (SOC2-CC7.2, ISO27001-A.8.16 and PCI-DSS-11), driven by the open
  Dependabot alert.
- **Not established:** private repositories, organization-wide settings,
  GitHub App installation tokens, GitHub Enterprise Server, and pagination
  beyond one page for any list (every list here fit in one page).
- **Compared with earlier runs:** no earlier live record.
